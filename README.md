# Kido Packages Registry (`@kido/*` Shared Architecture Library)

> **Purpose**: Single Source of Truth (SSoT) catalog of all **35 Cohesive Domain Combo Suites** in `kido-packages/packages/`.  
> **Anti-Fragmentation + Zero-Bloat Standard**: Related capabilities are grouped into **35 Domain Combo Suites**, while inside each package every sub-capability is strictly isolated in its own **`src/<slice>/`** directory with **zero cross-slice coupling**.

---

## ⚡ AI Agent Consumption Protocol (Shadcn-Style Surgical Cherry-Pick vs Tree-Shaken Import)

When an AI Agent needs a capability from `kido-packages`, it **NEVER** blindly clones an entire Combo Package into an external project:

1. **Mode A — Surgical Slice Extraction (Shadcn-UI Pattern — Default for External Repos)**:
   - Look up the capability in the tables below and read the **exact isolated slice path** (e.g., `packages/offline-sync/src/pg-replication/index.ts` or `packages/spa-version-guard/src/pwa-swr/preloadable-cache.ts`).
   - Every slice folder (`src/<slice>/`) is **100% self-contained** with zero dependencies on sibling slices in the same combo.
   - Copy/adapt **ONLY** the specific file or function needed into the target repo's `src/lib/` — **0 bytes of unused code, 0 extra `package.json` bloat**.
2. **Mode B — Tree-Shaken Package Import (For Apps inside `kido-packages/apps/*`)**:
   - Import from `@kido/<combo>` or `@kido/<combo>/<subpath>`. Bundlers (`tsup`, `Vite`, `Next.js`) tree-shake unused slices automatically.
3. **Rule for 5:30 AM Daily Harvester Agent**:
   - Always add new reusable features as a self-contained `src/<slice>/` folder inside one of the **35 existing Combo Suites**, re-export from `src/index.ts`, and document the exact `src/<slice>/` path in this registry.
