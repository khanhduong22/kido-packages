## 🔍 Core FinTech Invariants

1. **Zero-Drift Double-Entry Bookkeeping**: Every financial movement records paired balance transitions (`balanceBefore` -> `balanceAfter`) with strict `Sum(Debit) = Sum(Credit)` conservation and full replay verification (`auditLedgerIntegrity`).
2. **Stripe-Style Atomic Recovery-Point Idempotency**: Every payment or settlement transitions monotonically through persisted recovery checkpoints (`started -> locked -> ledger_posted -> completed`). Crashes or client retries resume cleanly from the last committed checkpoint without double-charging or double-crediting.
3. **Stateless Crypto Micro-Decimal Matching & Portfolio NAV**: Deterministic sub-cent micro-amount fingerprinting for on-chain deposit attribution alongside Weighted Average Cost Basis (WACB) portfolio tracking.

<Callout title="🤖 Financial Safety Invariant">
  Never mutate balances in place without an append-only ledger entry and an idempotency recovery key scoped to the caller mutation.
</Callout>

    ```python
    from decimal import Decimal
    from enum import StrEnum
    from dataclasses import dataclass

    class RecoveryPoint(StrEnum):
        STARTED = "started"
        LOCKED = "locked"
        LEDGER_POSTED = "ledger_posted"
        COMPLETED = "completed"

    @dataclass(frozen=True, slots=True)
    class JournalLine:
        account_id: str
        direction: str  # "DEBIT" | "CREDIT"
        amount: Decimal

    def verify_balanced_journal(lines: list[JournalLine]) -> None:
        debits = sum((l.amount for l in lines if l.direction == "DEBIT"), Decimal("0"))
        credits = sum((l.amount for l in lines if l.direction == "CREDIT"), Decimal("0"))
        if debits <= 0 or debits != credits:
            raise ValueError(f"Unbalanced journal entry: debits={debits}, credits={credits}")
    ```
