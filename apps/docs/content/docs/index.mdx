## 🎯 Core Philosophy: Karpathy `nanoGPT` + `shadcn` White-Box Reference

Modern backend engineering suffers from black-box dependency bloat: pulling in heavy libraries for concurrency locks, rate limiters, sharding routers, or ledger state machines. When an incident strikes at 3:00 AM, opaque library abstractions hide the exact concurrency boundaries and memory limits.

Kido Bag follows a clean white-box philosophy:

## 🚀 Two Ways to Adopt Kido Bag

<Tabs items={['Mode A: White-Box Copy & AI Agent Porting (Recommended)', 'Mode B: Surgical CLI & Monorepo Import']}>
  <Tab value="Mode A: White-Box Copy & AI Agent Porting (Recommended)">
    ### Mode A: Copy & Port Directly via Reference Spec (Python + TS)
    Fetch any page as clean Markdown via `/llms.mdx/docs/.../content.md` or read `/llms.txt`, inspect the **AI Agent Porting & Invariant Spec**, and copy the Python 3.12+ (`FastAPI` / `asyncio`) or TypeScript reference code directly into your repository:

    ```bash
    # Fetch the white-box markdown spec & dual-language code for @kido/hot-counter
    curl -fsSL https://bag.khanhdp.com/llms.mdx/docs/packages/02-concurrency-and-caching/hot-counter/content.md
    ```

    **Benefits:**
    - Zero external package manager dependencies or runtime lock-in.
    - Faithful cross-language porting to Python, TypeScript, Go, or Rust using explicit invariants.
    - Complete visibility during debugging and load tuning.
  </Tab>
  <Tab value="Mode B: Surgical CLI & Monorepo Import">
    ### Mode B: Surgical Slice CLI & Monorepo Import
    For TypeScript / Bun repositories, cherry-pick individual slices into `src/lib/` or import directly inside the `kido-packages` workspace:

    ```bash
    npx kido-bag add hot-counter/youtube-view-engine
    ```

    ```typescript

    import { SemanticVectorCache } from '@kido/resilient-cache/semantic-cache';
    ```
